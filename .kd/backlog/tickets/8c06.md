# Reconcile deferred vLLM release verification with independent core versions

Core 0.2.0 ships video while the deferred vLLM package remains 0.1.0 and requires qwen-mm==0.1.0. Default core-only release remains valid. The optional release-candidate verify-vllm:true path currently supplies core 0.2.0 to that plugin; assemble(include_plugin=True) also derives plugin version from core. Before re-enabling plugin publication, explicitly select compatible independent versions, update the pinned dependency after its security upgrade, and test optional verification/assembly. Discovered during c910 read-only release review; outside the authorized video core scope.

## Acceptance Criteria

- [ ] Optional verification selects a core wheel compatible with the independently versioned plugin, or fails early with an actionable version error.
- [ ] Plugin assembly derives its version from validated plugin metadata instead of the core version.
- [ ] Regression checks cover independent versions and the supported future plugin publication pair.
