# Evaluate optimized Pillow-compatible resize backend

D4 diagnostics show the scalar source-faithful Pillow resize port makes
single-image preprocessing roughly 45-49% slower than the official Pillow
baseline. Evaluate optimized native backends against the actual frozen resize
and end-to-end tolerances before writing more custom kernel code.

## Scope

- Benchmark the official Pillow 12.3.0 resize boundary separately from Python,
  decode, normalize, and patchify overhead.
- Evaluate mature optimized native candidates such as OpenCV, libvips, or an
  equivalent production resizer; direct reuse/adaptation of Pillow's native
  implementation; and SIMD/vectorization of the current source-faithful port.
- Test candidates against the complete resize corpus and Phase C output policy,
  not merely visual similarity or a single natural image.
- Record dependency, wheel/distribution, platform, memory, and thread-budget
  tradeoffs as well as latency.

## Non-goals

Do not widen the parity contract merely to make a candidate pass. A named
non-parity performance mode requires an explicit product decision. Do not
assume OpenCV or any other backend matches Pillow's bicubic-antialias semantics
without evidence.

## Acceptance Criteria

- [ ] The report distinguishes the pinned still-image path—Pillow bicubic in
      `qwen_vl_utils`, followed by Transformers with `do_resize=False`—from the
      separate TorchVision video path.
- [ ] At least two mature optimized implementations and the current scalar port
      are measured under identical inputs, output dimensions, warm state, and
      thread budgets on ARM and x86 where available.
- [ ] Every candidate is checked against the frozen per-channel resize bound and
      full lossless/lossy Phase C tensor tolerances, with exact error diagnostics.
- [ ] The selected option materially improves single-image latency without
      regressing the D4 many-image, memory, correctness, or distribution gates;
      otherwise the ticket documents the best rejected options and why.
- [ ] Full conformance and repository checks pass for any implementation change.

## Worklog

### 2026-08-13 — ticket created from D4 resize review

The current still-image implementation is a hand-written, scalar,
source-faithful port of Pillow 12.3.0's separable fixed-point resampler. The
top-level resize-stage contract permits a per-channel byte difference of one;
the selected port happens to be exact on the 17-case frozen corpus, but
universal bit-exactness was not the stated requirement. The only optimized Rust
candidate previously recorded was `fast_image_resize` 6.1.0 Catmull-Rom, which
failed 12 of 17 image cases and differed by up to 21 byte levels. OpenCV and
other mature native backends were not evaluated. Related active certification
ticket: `050f`.
