# Ship fast video preprocessing for frame lists, files, and mixed prompts

## Purpose and scope

Implement the production video path for the pinned Qwen3-VL and Qwen3.5 processors. Work inputs are predominantly video: accept lists of Pillow frames, NumPy/Torch decoded clips, TorchCodec-style decoded batches and metadata, local video files including MP4, and image/video mixtures in one conversation or heterogeneous batch. Preserve existing still-image behavior and optional Torch model outputs.

## Acceptance criteria

- [x] Original `type=video` messages accept inline frame lists, file paths/file URLs, decoded arrays/tensors, and separately indexed `videos`; Pillow also works for still-image occurrences.
- [x] Temporal padding, spatial sizing, normalization, patch order, grids, prompt timestamps, IDs, token types, occurrence order, and padding agree with pinned upstream workflows for both profiles within the established numeric resize contract.
- [x] FPS/frame-count sampling, explicit dimensions, pixel budgets, and clip boundaries are documented and tested. Decoded inputs preserve supplied frame timing/metadata and avoid accidental second sampling.
- [x] Mixed media, repeated references, heterogeneous batches, NumPy/Torch outputs, ownership/GIL release, and serial/parallel determinism work.
- [x] Malformed/empty clips, invalid rates/options, decode failures, and resource ceilings raise actionable stable errors without partial results.
- [x] Video preprocessing uses bounded native parallelism, avoids per-frame Python resize/normalization, and carries reproducible preprocessing and file-decode benchmarks with accurate speed claims.
- [x] Existing appropriate regression gates pass; a fresh installable wheel and runnable workplace examples are delivered. Public release/PR status is reported accurately.

3. Extend the PyO3 boundary with GIL-independent owned frame buffers, video option parsing and metadata, borrowed core requests, video arrays and integration sidecars. Preserve zero-copy output ownership and account for copied inputs.
4. Add Python media adapters: Pillow images/frame lists, THWC NumPy and TCHW Torch clips, TorchCodec frame batches/decoder objects, and optional file decoding with selective frame retrieval. Validate source metadata, choose sampling once, bound decoding, and expose usable optional dependencies.

## Current implementation and decisions

All seven implementation steps are complete in the working tree. Native video batching implements checked geometry, composed frame-list resizing, shared clip interpolation tables, fused normalization/packing, temporal padding, ordered mixed-media prompt expansion, exact output destinations, sidecars, and bounded processor-owned Rayon parallelism. PyO3 owns input buffers across GIL release and transfers output arrays to NumPy without copies.

The public adapter accepts Pillow stills/frame lists, NumPy/Torch decoded clips, prepared metadata tuples, TorchCodec FrameBatch PTS and decoder objects, files/URLs/encoded video, and repeated or mixed media. Files prefer working TorchCodec and fall back to optional PyAV; selected-frame retrieval/RGB conversion is bounded. Decoded clips preserve caller sampling. Plain frame lists follow the pinned utils factor64 first resize and synthetic odd-padding index; decoded clips duplicate the last original timestamp. Prepared integral-float tuples avoid a second resize. Clip totals/sample rates use inclusive clipped counts while indices retain absolute positions. Long-file sampling reproduces PyTorch CPU float32 linspace rounding; cache identity preserves full timestamp precision. Resource preflight occurs before decoder retrieval, unknown-count scans, host copies, or pixel allocation where source dimensions are available.

Core/Python version is 0.2.0. The optional video extra supplies PyAV/Pillow. The vLLM package remains independent at 0.1.0 with its existing still-image scope. Release tooling supports these independent versions. Public usage and support boundaries are documented in docs/video-v0.2.md. Historical v0.1 image measurements retain their original provenance.
