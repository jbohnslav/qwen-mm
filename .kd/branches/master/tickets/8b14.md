# A5: Build the paired benchmark v2

## Goal

Replace the directional one-host timing script with an apples-to-apples harness
that can support later parity-preserving performance claims.

## Scope

- Give the official and future Rust adapters the same encoded-to-NumPy and
  RGB-to-vLLM-ready boundaries.
- Validate complete outputs around timing and control threads, warm state, case
  data, and process-level repetition explicitly.
- Record raw data and uncertainty; do not enforce the final `2x` gate on noisy
  pull-request workers.

## Acceptance Criteria

- [x] Reference and candidate adapters share the same case schema, messages,
      bytes/buffers, output `float32`/`int64` contract, and timer boundaries.
- [x] The suite includes text-only, current `image1`/`image24`, 24 independent
      requests, ragged formats/shapes, aligned inputs, resize boundaries, raw
      RGB, repeated/cache-separated inputs, and scaling cases.
- [x] Every timed implementation passes full key/value/dtype/shape conformance
      before and after measurement; measured iterations cannot silently change
      outputs.
- [x] The protocol supports fresh-process repetitions, randomized AB/BA order,
      warmups, minimum time/sample counts, one-thread and equal production-thread
      regimes, and shipping versus native build labels.
- [x] Results record samples plus p50/p90, qualified p99, throughput, CPU time,
      peak RSS, transient live bytes, allocation/copy counts, thread settings,
      environment, and bootstrap 95% confidence intervals.
- [x] A versioned JSON result schema and readable report are produced, with ARM
      and x86 results kept separate.
- [x] Pull-request smoke and dedicated-host enforcement modes are documented;
      final thresholds remain owned by D4.

## Worklog

2026-07-31 — started and implementation plan

- Started A5 as the hand after its A1/A2 dependencies closed. A3 is also active
  in another live checkout context with uncommitted conformance/corpus files; A5
  will preserve those edits and stay isolated to benchmark-specific paths plus
  narrowly scoped build/documentation hooks.
- The existing `qwen_mm_reference.bench` runner is a directional official-only
  warm-process script. It covers only `image1`/`image24`, checks a first-output
  hash signature rather than full iteration stability, and does not provide
  paired process ordering, resource metrics, uncertainty, a versioned schema,
  or CI/dedicated-host modes.
- Planned delivery sequence: (1) define a versioned workload and result contract
  shared by reference and candidate adapters; (2) implement pre/post and
  per-iteration full-output conformance around timed regions; (3) add fresh
  process AB/BA orchestration, thread/build regimes, raw resource samples, and
  bootstrap confidence intervals; (4) add JSON validation and readable reports;
  (5) wire deterministic tests, smoke/full commands, and documentation.
- The harness will consume the A1 output contract and A2 case/golden artifacts.
  Where A3's comparator is available it can be used as the richer diagnostic
  layer, while benchmark execution retains an independent exact structural and
  value-stability guard so timing can never continue on drifting outputs.

2026-07-31 — paired benchmark v2 implemented

- Added versioned workload and result schemas under `benchmarks/`, plus a
  deterministic matrix covering text, historical `image1`/`image24`, 24
  independent requests, ragged JPEG/PNG/lossless-WebP inputs, aligned and resize
  boundaries, caller-owned RGB, repeated cached/uncached/cache-separated inputs,
  and 1/4/16/32/64-image scaling.
- Added a shared immutable `CasePayload` adapter protocol. Input fingerprints
  cover exact messages, bytes, RGB values, formats, and lossless provenance;
  paired subprocesses reject any mismatch. The built-in official adapter uses
  the pinned Transformers/Qwen VL Utils path, and external Rust candidates plug
  in through a `module:factory` adapter without changing timer boundaries.
- Each fresh worker loads a primary adapter plus an untimed oracle, performs full
  key-order/dtype/shape/stride/value checks before and after measurement, and
  checks every timed output for exact stability after stopping the timer. Mixed
  codec batches apply per-occurrence strict versus lossy final-pixel tolerances
  using grid-derived patch ranges.
- Added randomized AB/BA process scheduling, configurable fresh repetitions,
  warmups, minimum sample/time requirements, one/production thread budgets,
  shipping/native labels, raw wall/CPU/throughput/core/RSS/live-byte/allocation/
  copy samples, qualified p99, paired process speedups, and seeded bootstrap 95%
  confidence intervals.
- Added Markdown reporting, architecture-family isolation, package/model/thread
  provenance, `make benchmark-v2-self-test`, candidate-driven
  `make benchmark-v2-smoke`, and documented smoke versus dedicated-host modes.
  The protocol explicitly records no performance enforcement; D4 retains all
  release threshold ownership.
