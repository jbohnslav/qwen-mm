# B6: Implement decode and color semantics

## Goal

Turn supported encoded images and caller-owned raw RGB into the canonical
prepared RGB bytes expected by B4, with exact pinned color, orientation,
resize, safety, and error behavior.

## Scope

- Land JPEG first, then PNG and WebP, using exact-pinned Rust dependencies and
  B5's accepted image resize implementation.
- Support encoded grayscale, alpha-bearing, and CMYK inputs with the frozen RGB
  conversion behavior; intentionally ignore EXIF orientation in parity mode.
- Accept caller-owned positive-stride RGB8 views permitted by A1, validate
  dimensions/row stride/buffer extent, and preserve their bytes exactly before
  any required resize.
- Parse and enforce byte, edge, decoded-pixel, prepared-pixel, and output limits
  before large allocations; map unsupported/corrupt/truncated/malformed inputs
  to the deterministic stable error categories.

## Non-goals

Do not fetch URLs or paths, accept PIL objects or arbitrary tensor/color
formats, correct EXIF orientation, decode video, add caching, or parallelize.

## Acceptance Criteria

- [x] Caller-owned RGB and lossless decode before resize are byte-exact; PNG and
      lossless WebP prepared RGB are exact; JPEG and lossy WebP prepared RGB
      differ by at most one byte per channel at identical dimensions.
- [x] Grayscale, RGBA/alpha, and CMYK fixtures match the pinned RGB conversion;
      EXIF orientation-tag cases prove the stored raster is used without
      transpose.
- [x] JPEG, PNG, and WebP cover aligned/no-op and B5 resize cases, unusual
      dimensions/aspects, truncation/corruption, unsupported modes/codecs, and
      malicious or oversized headers.
- [x] Valid positive-stride RGB views match packed RGB exactly; zero/short/
      inconsistent/overflowing dimensions, stride, or extent fail before any
      out-of-bounds read or partial output.
- [x] Decoder and allocation preflight enforce all relevant B1 limits and map
      failures distinctly to `unsupported_media`, `media_decode`,
      `media_geometry`, `resource_limit`, or `arithmetic_overflow` in the frozen
      precedence.
- [x] The prepared-RGB stage passes A2/A3 conformance with full mismatch
      localization on macOS ARM and Linux x86, without Python at runtime.
- [x] Exact dependency pins and codec feature choices are documented; core
      unit/doc tests, conformance-smoke, format, and Clippy checks pass.

### 2026-08-01 — implementation and independent review complete

Implemented bounded Rust-only JPEG, PNG, WebP, and caller-owned strided RGB8
preparation with the frozen color, EXIF, alpha, resize, resource, corruption,
and error-precedence behavior. Exact-pinned `image=0.25.10` is restricted to
PNG/WebP and `libjpeg-turbo-rs=0.8.0` owns JPEG; the rejected zune-jpeg path is
not linked. The B5 image kernel was corrected to a source-faithful Pillow
fixed-22-bit/i32 implementation after the first lossless off-grid PNG gate
found a one-byte mismatch.

lossless/lossy WebP including VP8X alpha, EXIF 1-8, raw packed/padded views,
boundary geometry, animation, truncation, malicious headers, parser collisions,
and every stable error category. Both supported profiles pass 116/116 report
rows with maximum error zero on native macOS arm64 and Linux x86_64 under
explicitly labeled QEMU emulation. A fresh double regeneration produced
byte-identical artifacts and matched the committed manifest and blobs.

Lord verification passed `git diff --check`, Cargo format, workspace Clippy
with `-D warnings`, all 69 runnable core all-target tests (8 intentionally
