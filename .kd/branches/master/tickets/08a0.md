# C1: Implement the two-phase serial batch API

## Goal

Extend the Phase B single-request processor into a serial, heterogeneous native
batch API with a validated plan, exact output capacities, caller-owned
destinations, and an allocating convenience wrapper. Planning and execution
must make allocation, ordering, overflow, and failure atomicity explicit before
the Python boundary is added.

## Scope

- Implement `plan_batch(requests)` to validate the full batch and return a
  reusable `BatchPlan` plus exact capacities for every conditional public
  output.
- Complete every fallible decode and geometry stage during planning, after
  aggregate capacity preflight, and retain the prepared RGB snapshot needed for
  repeatable execution. Destination validation remains later in the frozen
  stage order.
- Implement `execute_plan_into(plan, destinations)` to fill validated
  caller-owned destinations and return a `PreparedBatchView` without changing
  request, visual-occurrence, token, patch, or grid order.
- Implement allocating `prepare_batch(requests)` as the convenience wrapper over
  the same planning and execution semantics.
- Support heterogeneous text-only and image requests, encoded and caller-owned
  RGB inputs, per-request padding, the official conditional key set, and exact
  `int64`/`float32` public storage.
- Carry the frozen contract ID and full profile fingerprint and return one
  content-bound stable cache identity per image occurrence before tensors are
  flattened, as required by the closed A6 seam contract. The key covers source
  content and every image option that affects prepared pixels; repeated
  references with the same content/options may reuse it while occurrence ranges
  remain request-local.
- Validate checked capacity arithmetic, aggregate resource limits, aliases or
  incompatible destinations where relevant, and undersized destinations before
  any externally observable write.
- Bind plans to their immutable contract/profile/limit context and reject a
  stale or wrong-processor plan before any destination write.
- Preserve the Phase B error-precedence and conformance semantics across
  multiple requests, including deterministic failure selection.

## Non-goals

Do not add PyO3/NumPy bindings, request or visual parallelism, speculative
fusion/arenas, certified performance claims, video support, caching, or the
production vLLM adapter.

## Acceptance Criteria

- [x] `plan_batch` accepts heterogeneous batches and reports exact checked
      capacities, shapes, offsets, and padding requirements for every output;
      overflow and aggregate-limit failures occur before full media execution.
- [x] `execute_plan_into` produces deterministic official ordering and exact
      output metadata for sufficiently sized destinations at their documented
      dtypes and layouts.
- [x] An undersized or otherwise invalid destination fails before any
      destination is modified; tests cover each output buffer and late batch
      validation failures.
- [x] Error-stage tests prove aggregate resource excess wins before full decode,
      corrupt recognized media fails during planning, and destination errors
      occur only for an otherwise fully executable plan without changing any
      caller sentinel.
- [x] `prepare_batch` returns the same values, shapes, key presence, and errors
      as plan-plus-execute for text-only, mixed-size, mixed-codec, raw-RGB,
      interleaved, repeated-image, empty, and multi-request batches.
- [x] Batch error precedence, resource limits, checked arithmetic, padding, and
      deterministic request/occurrence ordering have focused regression tests.
- [x] Results expose the exact contract ID, profile fingerprint, per-occurrence
      pixel spans, and deterministic content-bound cache identities required by
      A6; tests cover reuse and separation by source, profile, and image options.
- [x] A plan can be executed repeatedly by a compatible processor, while a
      stale or wrong-contract/profile/limit plan is rejected before writes.
- [x] The existing Phase B corpus remains unchanged and green, and the full
      Rust and repository correctness suites pass.

### 2026-08-02 — A6 downstream contract restored to C1 scope

The independent test audit found that the initial C1 ticket transcription did
not state two requirements carried by its explicit A6 dependency.
`docs/vllm-prepared-pixel-seam.md` requires the batch result to preserve the
contract ID, full profile fingerprint, per-occurrence pixel spans, and a stable

requires stale plans to be rejected before caller memory is written. Added both
requirements and their focused tests to C1 rather than deferring a known seam
contract until C2/F1.

### 2026-08-02 — planning/execution boundary clarified

The adversarial audit traced the frozen validation order through
`docs/compatibility-v1.md`: resource preflight precedes decode/geometry, which
in turn precede destination validation. C1 will therefore finish every fallible
media stage and retain prepared RGB in `BatchPlan`; execution first validates
all destinations and then performs only prevalidated writes. This makes a plan
reusable, preserves decode-before-destination error precedence, and gives the
no-partial-write guarantee a mechanically testable boundary.

### 2026-08-02 — public API shape selected after independent audit

The API audit selected an owned, non-`Clone` `BatchPlan` with no caller-input
lifetime: it retains token/prompt metadata, prepared RGB, prevalidated patch
plans, exact official layouts, and the contract/profile/limit identity.
`BatchDestinations` uses typed mutable slices for all official fields (video
slots are reserved but absent in C1), and `PreparedBatchView` returns exact
immutable prefixes plus plan metadata. Safe Rust makes overlapping mutable
slices unrepresentable at the core boundary; C2 must separately reject
overlapping foreign NumPy buffers before constructing Rust borrows.

### 2026-08-02 — full-suite review found a Phase B API regression

The first workspace-wide `make check` passed Python lint/format, Rust format,
and strict workspace Clippy, then failed while compiling the Phase B
conformance example: C1 had added `cache_key` directly to the existing public
`ProcessedImageOccurrence` struct, so the example's constructor no longer
compiled. The focused core tests did not compile examples and therefore missed
the regression. C1 remains open; the fix must preserve the Phase B result type
while exposing cache identity through the new batch-specific surface, followed
by another full-suite run.

### 2026-08-02 — independent code review corrections

After the Phase B type regression was repaired with a new batch-specific
occurrence wrapper, the API review found three additional issues before C1
acceptance. Batch planning rejected video requests before comparing them with
image resource/decode failures in global occurrence order; the legacy Phase B
path unnecessarily hashed every source even though it discards batch cache
identity; and raw-RGB cache keys encoded `usize`, making identities differ
between 32-bit and 64-bit hosts. C1 remains open while batch-only error
selection is unified, hashing is removed from the legacy path, dimensions and
lengths are canonicalized to fixed-width integers, and regression tests lock
the behavior.

### 2026-08-02 — implementation accepted

Implemented the owned, reusable, non-`Clone` `BatchPlan`, exact checked batch
capacities and layouts, caller-owned atomic execution, and the allocating
wrapper. Planning completes all fallible media work after aggregate preflight;
execution validates contract/profile/limits and all seven official destination
slots before its first write. Batch metadata carries contract/profile identity,
per-occurrence global ranges, sidecar coordinates, and a fixed-width SHA-256
cache identity over profile, logical source content, and pixel-affecting
options.

Two read-only Codex reviewers audited the final diff; no Kingdom peasant was
used. Their findings drove preservation of the Phase B occurrence type, global
video/image error ordering, batch-only portable hashing, post-validation raw
hashing, and literal JPEG/mixed-geometry/wrong-contract coverage. Final
verification passed `make check`, all 22 asset-backed ignored core tests, the
complete ignored Phase B example, the two-profile Phase B report (10/10 cases),
strict workspace Clippy, wheel smoke, reference tests, conformance smoke, and
`git diff --check`.
