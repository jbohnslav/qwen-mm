# D2: Implement deterministic bounded parallelism

## Goal

Parallelize independent requests and visual occurrences through a
processor-owned, explicitly bounded worker pool while preserving the serial
Phase C contract exactly. The caller's thread budget must remain the total
budget rather than multiplying through Rayon, tokenizers, PyTorch, or vLLM
nested pools.

## Scope

- Add an owned pool with explicit construction/configuration, a deterministic
  one-thread mode, and a documented finite upper bound; do not use Rayon's
  process-global pool implicitly.
- Parallelize only D1-identified request or visual stages whose independence is
  proven, while retaining deterministic request, occurrence, token, patch,
  grid, sidecar, and destination ordering.
- Preserve the frozen validation and error-precedence rules: multiple failures
  must select the same stable typed error as the serial path regardless of task
  completion order or thread count.
- Coordinate or document nested-runtime controls so tokenizers and embedding
  environments such as PyTorch/vLLM cannot oversubscribe the processor pool by
  default.
- Exercise thread counts 1 through N across heterogeneous, ragged, repeated,
  boundary, malformed, and resource-limit cases, including repeated stress
  runs capable of exposing races or accidental shared state.
- Record diagnostic throughput, CPU utilization, peak transient memory, and
  scaling for representative many-image cases; final performance enforcement
  remains in D4.

## Non-goals

Do not land speculative normalize/layout fusion or arenas unless independently
owned by D3. Do not claim the final `2x` speedup, add cross-request caching,
video support, or implement the vLLM adapter.

## Acceptance Criteria

- [x] A processor instance owns a bounded pool with an explicit total thread
      budget, deterministic one-thread behavior, clean lifecycle, and no
      implicit use of a process-global native pool.
- [x] Results for every supported thread count from 1 through N are byte- and
      metadata-exact with the serial candidate for both profiles, including
      conditional keys, dtypes, shapes, strides, all ordering, and sidecars.
- [x] Concurrent-error tests prove stable validation stage, typed error, and
      failing request/media selection independent of scheduling and thread
      count, with no partial caller-destination writes.
- [x] Race/stress tests cover mixed encoded/raw inputs, ragged batches,
      repeated references, empty/text-only requests, malformed media, resource
      limits, pool reuse, and multiple processor instances.
- [x] Default configuration and integration tests prove the configured thread
      budget is not silently multiplied by Rayon or tokenizer parallelism and
      provide documented controls for PyTorch/vLLM hosts.
- [x] Diagnostic scaling evidence ties the chosen parallel boundaries to D1's
      profiles and reports throughput, utilization, and transient-memory
      behavior without presenting an uncertified release claim.
- [x] Full C3 image conformance for both profiles and the full repository
      correctness suite pass with representative thread-count sweeps.
