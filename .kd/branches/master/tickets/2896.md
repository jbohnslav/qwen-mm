# B3: Implement geometry and smart_resize

## Goal

Implement the pure, allocation-free image geometry rules exactly before any
pixel kernel can obscure rounding, boundary, or overflow errors.

## Scope

- Implement factor rounding and Qwen VL Utils `smart_resize` behavior for the
  frozen factor, default/explicit minimum and maximum pixel budgets, paired
  explicit dimensions, and aspect-ratio limit.
- Match Python ties-to-even rounding at half boundaries without depending on
  host floating-point rounding mode.
- Produce checked destination dimensions, `image_grid_thw`, placeholder/patch
  counts, and capacities that later pixel stages can consume.
- Use B1 limits and stable errors for zero dimensions, invalid option
  combinations, excessive aspect ratios/resources, and arithmetic overflow.

## Non-goals

Do not decode media, choose a resize implementation, touch pixel values,
implement temporal sampling, or broaden parity semantics beyond the frozen
image rules.

## Acceptance Criteria

- [x] Every A3 factor-32 and image `smart_resize` rule passes exactly, including
      the 16/48/80/112 half ties, default/explicit min/max transitions, exact
      budget, aspect ratio 200 boundary, and paired explicit dimensions.
- [x] Dimension, grid, placeholder, patch-row, byte-capacity, and stride
      calculations use checked integer arithmetic and agree exactly with the
      oracle for supported inputs.
- [x] Zero/invalid dimensions, unpaired explicit dimensions, `max_pixels <
      min_pixels`, aspect ratio over 200, resource excess, and overflow return
      the frozen stable category with deterministic validation precedence.
- [x] Boundary and property tests cover one step below/at/above each transition,
      very large operands, portrait/landscape symmetry, and no-op aligned sizes.
- [x] The implementation is deterministic across supported ARM and x86 targets
      and does not allocate proportionally to the image size.
- [x] Core unit/doc tests, conformance-smoke, format, and Clippy checks pass.
