# B5: Prove resize parity

## Goal

Select or implement Rust resize kernels from conformance evidence, not speed or
API convenience, and freeze the decision before decoding lands.

## Scope

- Build a stage harness that feeds identical source pixels and B3 destination
  geometry to candidate Rust kernels and the pinned Pillow image / TorchVision
  bicubic-antialias video references.
- Cover upsample, downsample, no-op, aligned/off-grid, aspect-ratio, min/max,
  high-frequency, edge, and color-channel cases on supported ARM and x86 hosts.
- Record dimensions and the full frozen diagnostics for each candidate; explain
  interpolation, coordinate, antialias, rounding, clamping, and color-domain
  behavior where results differ.
- Exact-pin and justify any selected dependency, or document and test the custom
  kernel if no maintained dependency passes.

## Non-goals

Do not choose a kernel because it benchmarks well, widen A1 tolerances, hide a
platform-specific failure, implement encoded-media decoding, or make an
end-to-end performance claim.

## Acceptance Criteria

- [ ] The image corpus matches pinned Pillow dimensions with per-channel RGB8
      absolute error at most one for every pixel and reports all required
      diagnostics for any mismatch.
- [ ] The video corpus matches pinned TorchVision bicubic+antialias in its
      `0..255` `float32` domain with `rtol=0`, `atol=1e-4`, even though video is
      not exposed by the Phase B API.
- [ ] Cases cover no-op, representative up/down ratios, off-grid dimensions,
      factor/min/max boundaries, portrait/landscape inputs, impulses, ramps,
      checkerboards, and independent RGB channels.
- [ ] Results are recorded separately for macOS ARM and Linux x86; a selected
      implementation passes both or an explicit implementation ticket/blocker
      is recorded instead of weakening the gate.
- [ ] A tracked decision record names the evaluated candidates, exact versions,
      evidence, selected implementation, and consequences for B6 and Phase E.
- [ ] The selected image/video resize entry points are covered by deterministic
      stage tests and can consume B3 plans without Python/Torch at runtime.
- [ ] Core checks and the resize-stage conformance suite pass from a clean
      checkout.
