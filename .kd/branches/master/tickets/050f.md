# D4: Certify image performance

## Goal

Run the complete controlled-host protocol against the optimized Phase D image
path and publish the reproducible evidence required for the roadmap's `2x` CPU
claim. Certification is valid only while complete pre/post conformance remains
current and the reference and candidate use identical inputs, structural
outputs, warm state, dtypes, profiles, and total thread budgets. Image numeric
values follow the predeclared neural-image fidelity contract selected in `4d7f`;
Pillow pixel identity is not required.

## Scope

- Run the entire A5 image/text workload matrix on a controlled native macOS ARM
  host and a controlled native Linux x86 host, keeping architecture results
  separate. An allocated Modal x86 worker is eligible real performance and
  certification evidence when its CPU allocation, cgroup/affinity state,
  repeatability, and runtime provenance satisfy the same protocol; it is not
  restricted to synthetic or non-releasable smoke evidence.
- Use five fresh processes per implementation, randomized AB/BA order, at least
  30 samples and five seconds per core case, fixed CPU placement where
  available, and both one-thread and equal production-thread regimes.
- Run conformance immediately before and after every timed run and reject
  missing keys, structural drift, a violation of the frozen image-fidelity
  envelope, fallback work, input drift, unequal thread budgets, or
  non-comparable build/runtime state.
- Report p50/p90, qualified p99, throughput, CPU time, peak RSS, transient live
  bytes, allocation/copy counts, core utilization, raw samples, and bootstrap
  95% confidence intervals for speedup.
- Enforce the headline speed, single/text regression, parallel-efficiency, and
  transient-memory thresholds from the roadmap and publish both machine-
  readable evidence and a concise human-readable conclusion.
- Bind the report to exact source, benchmark schema, conformance report,
  processor/profile/model artifacts, package/native artifact, host, compiler,
  environment, affinity, and thread-control provenance.

## Non-goals

Do not substitute an uncontrolled or demonstrably noisy shared runner for
controlled-host certification, merge ARM and x86 results, certify video, infer
production vLLM gains, or change the gate after observing results. Modal is not
disqualified by provider name: accept or reject a run from its captured host
and variance evidence. A miss remains a measured miss and reopens the relevant
optimization ticket rather than weakening the contract.

## Acceptance Criteria

- [ ] All timed reference and candidate runs pass complete conformance
      immediately before and after measurement for both profiles with identical
      encoded/RGB inputs, messages, structural outputs, `float32`/`int64` dtypes,
      warm state, profile, build labels, and total thread budgets; image numeric
      drift remains inside the candidate-independent contract frozen by `4d7f`.
- [ ] On both controlled ARM and controlled Linux x86 hosts, the lower bound of
      the bootstrap 95% speedup confidence interval is at least `2.0x` for
      `jpeg24_one_request` and `ragged24`.
- [ ] On the current M4 baseline, candidate `image24` point estimates are below
      111.0 ms for Qwen3-VL and 111.6 ms for Qwen3.5, or the report explicitly
      records why the roadmap's initial-point target is not met while still
      refusing certification.
- [ ] For every applicable image case in the frozen D4 matrix, both profiles,
      architectures, and comparable thread regimes, the candidate is faster
      than the official baseline; text-only cases regress by no more than 5%.
- [ ] A many-image case demonstrates at least 60% parallel efficiency through
      eight physical cores without exceeding the declared total thread budget.
- [ ] Peak transient live bytes, excluding the retained final output, are no
      more than 50% of the official path, and the allocation census proves no
      full `float32` CHW intermediate image exists.
- [ ] Versioned raw JSON and a readable report preserve all required samples,
      percentiles, utilization, allocation/memory data, confidence intervals,
      host/build/runtime provenance, commands, and separate ARM/x86 results.
- [ ] Report/schema/currentness validation, clean-checkout reproduction of
      non-host-specific artifacts, and the full repository correctness suite
      pass; the report makes no production or video claim.

## Worklog

### 2026-08-13 — performance-first resize contract and new dependency

The King explicitly rejected Pillow pixel identity as the deciding optimization
criterion and required the image path to beat the official baseline in every
applicable case. D4 now depends on `4d7f`, which will select a maintained,
open-source Rust-native resizer without a heavyweight OpenCV/libvips wrapper.
Geometry, public structure, dtypes, grids, ordering, limits, and error behavior
remain exact. A candidate-independent natural-image fidelity envelope will be
frozen before performance selection; adversarial Pillow byte equality will not
veto an otherwise sound neural-network preprocessing path. The 2x batch,
parallel-efficiency, memory, provenance, and controlled-host gates remain.

### 2026-08-03 — pre-capture adversarial review and protocol hardening

Independent review stopped the first certifying launch before any paid Modal
capture. The raw runner originally exposed no messages-only digest and restarted
its randomized schedule in four independent thread-budget invocations while the
certifier assumed one global schedule. Both contracts now agree on the exact
fixed seed (`20260731`), each raw pair preserves its authenticated local order
seed, and workers publish a canonical messages-only fingerprint instead of
mislabeling the logical media fingerprint.

Fast text operations also made the literal five-second loop large enough to
threaten the bounded archive. The final protocol retains exactly 30 genuine
one-operation samples per process for latency percentiles. Additional
individually clocked, exact-output-checked operations are summarized only in a
separate timing-floor counter and never enter p50/p90. This preserves the
unchanged five-second requirement without pruning samples or introducing
variable-size batch means.

The same review tightened the total CPU allowance to `N + 0.25` cores, fixed
the random seed across hosts, changed summary latency to equally weighted fresh
process medians, made transient-memory gating conservative per process pair,
preserved physical-core topology/masks, bound certification captures to the raw
archives, and made archive ingestion revalidate every raw benchmark and
recompute the no-pruning CV rule. Portable validation accepts an archived Phase
C report only through an explicit authenticated report/assets override.

The installed `py-spy==0.4.1` development pin remains available for escalation;
`line-profiler` was not added because the current risk diagnostic localizes the
single-image gap in the native scalar resize stage, not Python execution.

### 2026-08-03 — certification implementation started

D3 closed on exact committed source with 290/290 current Phase C conformance,
unblocking D4. The certification gates are frozen before observing D4 data:
shipping builds are the release gate, native builds are supplemental; the
production budget is eight; scaling is enforced at t2/t4/t8; the paired
bootstrap uses 20,000 deterministic resamples; and timing is isolated from
profilers, `tracemalloc`, observation spans, and resource census work.

retain and explicitly report that unsupported row, but will reject any artifact
that relabels ordinary uncached work as cached performance. This does not weaken
any speed, regression, scaling, memory, correctness, or provenance threshold.

Implementation is split across independent agent-owned seams: safe raw timing
and affinity/resource capture, strict certification schema/evaluation, and the
Modal/local build-and-capture runners. The Hand owns integration, review,
