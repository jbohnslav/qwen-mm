# Phase D: Profile, optimize, and certify speed

## Goal

Turn the conformant serial Phase C image processor into a measured, bounded,
parallel native implementation and certify that it meets the roadmap's CPU,
scaling, regression, and transient-memory gates on controlled ARM and x86
hosts. Optimization remains subordinate to the frozen parity contract: every
change must preserve the complete public output and error behavior for both
profiles.

## Child Tickets

- D0 / `ccbc` — prove a minimal native Linux x86 Modal benchmark runner.
- D1 / `e182` — add native observability and publish ARM/x86 profiles.
- D2 / `6841` — implement deterministic bounded parallelism.
- D3 / `676e` — apply only profile-justified fusion and arena reuse.
- D4 / `050f` — run and publish image performance certification.

## Execution Shape

D0 starts from the closed A5 benchmark harness and C3 image-conformance gate and
proves only the minimal Modal runway. D1 follows D0. D2 then follows D1. D3 also
follows D1, reuses C1's two-phase caller-buffer API, and may proceed
independently of D2. D4 begins only after both optimization tracks close and
reasserts A5 and C3 as release prerequisites. The epic depends on all five
children, so it is a completion roll-up rather than executable implementation
work.

## Scope Boundaries

This phase covers the text/image CPU path at the official `float32`/`int64`
boundary. Raw-frame and encoded-video support belongs to Phase E; the vLLM
adapter and production canary belong to Phase F. Cross-request content caching,
compact integer outputs, and `bf16` performance claims remain deferred. Phase D
must not widen frozen tolerances or trade correctness for benchmark results.

## Acceptance Criteria

- [ ] D0 through D4 are closed with implementation, profiling, conformance, and
      verification evidence recorded in their worklogs.
- [ ] Whole-operation ARM and x86 profiles identify and rank the actual
      bottlenecks before fusion or arena changes are accepted.
- [ ] Parallel execution uses a processor-owned bounded pool and preserves
      exact outputs, ordering, and stable errors at every supported thread
      count without default nested-pool oversubscription.
- [ ] Every fusion, scratch-reuse, arena, or caller-buffer change is justified
      by profile evidence, measured in isolation, and followed by the complete
      image conformance gate for both profiles.
- [ ] Controlled ARM and x86 certification meets every `ROADMAP.md` image CPU
      speed, guard-regression, scaling, and transient-memory threshold.
- [ ] Versioned raw benchmark JSON, readable performance reports, profile
      artifacts, commands, and provenance are published beside current passing
      correctness evidence and validate from a clean checkout.
- [ ] The full repository correctness suite passes, and `ROADMAP.md` changes
      only if Phase D evidence changes a downstream dependency, threshold, or
      scope assumption.
