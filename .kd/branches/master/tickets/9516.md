# Phase D: Profile, optimize, and certify speed

## Goal

Turn the conformant serial Phase C image processor into a measured, bounded,
parallel native implementation and certify that it meets the roadmap's CPU,
scaling, regression, and transient-memory gates on controlled ARM and x86
hosts. Every change must preserve exact public structure and error behavior for
both profiles. Resize pixels follow a frozen neural-image fidelity envelope
rather than requiring identity with Pillow's implementation.

## Child Tickets

- D0 / `ccbc` — prove a minimal native Linux x86 Modal benchmark runner.
- D1 / `e182` — add native observability and publish ARM/x86 profiles.
- D2 / `6841` — implement deterministic bounded parallelism.
- D3 / `676e` — apply only profile-justified fusion and arena reuse.
- D3.5 / `4d7f` — select and integrate the fastest suitable Rust image resizer.
- D4a / `cb29` — wire and validate the compact performance capture pipeline.
- D4b / `cd33` — run and publish compact ARM/x86 certification.
- D4c / `725c` — run the bounded ARM optimization pass for v0.1.
- D4d / `f49c` — run the bounded multithreaded optimization pass for v0.1.
- D4e / `b2a2` — post-v0.1 strict ARM batch-memory certification.
- D4f / `8b8c` — post-v0.1 strict single-image memory certification.
- D4g / `82fe` — post-v0.1 strict x86 reference-noise certification.
- D4 scope / `685b` — define the pragmatic v0.1 release gate separately from
  strict Phase D certification.

Current compact status: **MISS**. D4b published valid evidence from identical
ARM/x86 source revision `5a77e78c85e0ef11da154d573fb405abb9c9780b`; 107 of
122 gates passed and 15 missed. The epic remains open on D4c–D4g, and no
threshold, dependency outside Phase D, or scope assumption has been relaxed.

## Execution Shape

D0 starts from the closed A5 benchmark harness and C3 image-conformance gate and
proves only the minimal Modal runway. D1 follows D0. D2 then follows D1. D3 also
follows D1, reuses C1's two-phase caller-buffer API, and may proceed
independently of D2. D3.5 follows the measured D4 single-image regression. D4a
finishes the compact benchmark tooling after all optimization tracks close, and
D4b then runs and publishes the controlled evidence while reasserting A5 and C3
as release prerequisites. Its measured miss fans out into D4c–D4g, each scoped
to a disjoint failure family. The epic depends on D4b and all five follow-ups,
so it remains a completion roll-up rather than executable implementation work.

## Scope Boundaries

This phase covers the text/image CPU path at the official `float32`/`int64`
boundary. Raw-frame and encoded-video support belongs to Phase E; the vLLM
adapter and production canary belong to Phase F. Cross-request content caching,
compact integer outputs, and `bf16` performance claims remain deferred. Phase D
keeps exact structure and errors, but intentionally replaces Pillow pixel
identity with a predeclared neural-image fidelity envelope. Every selected
compact image benchmark coordinate must beat the official baseline. The former
exhaustive matrix is deferred and cannot be claimed by the compact result.
