# Prepare and verify v0.1 release artifacts

## Goal

Turn the approved still-image/text implementation into reproducible,
installable v0.1 artifacts for native macOS ARM and Linux x86 with an honest
support statement and reversible publishing rehearsal.

## Scope

- Add the visible license and complete Python package metadata required for the
  intended distribution channel.
- Add changelog/release notes, installation instructions, platform/Python/model
  support matrix, and explicit video/vLLM exclusions.
- Build native release wheels and any chosen source distribution from the exact
  candidate commit; record hashes and build provenance.
- Install artifacts into fresh environments and run public examples, wheel
  smoke, binding/ownership tests, conformance, and repository checks.
- Add or document the native release automation needed to reproduce both
  platform artifacts.
- Rebuild the final release evidence after all source and documentation changes
  so currentness refers to the release candidate, then rehearse publishing
  without making the public release.

## Non-goals

Do not publish, create a public release, or allocate paid x86 benchmark compute
without the separate approvals those actions require. Do not imply Windows,
additional Python versions, video, or vLLM support.

## Acceptance Criteria

- [ ] License, package metadata, changelog, install guide, support matrix, and
      release notes are complete and internally consistent at version `0.1.0`.
- [ ] Native macOS ARM and Linux x86 artifacts build reproducibly from the
      exact candidate source and retain recorded hashes/provenance.
- [ ] Fresh-environment installs pass the public examples, wheel smoke,
      binding/ownership tests, conformance, and the full repository check.
- [ ] Final release evidence and human-readable status reflect the exact
      candidate source and its deliberately narrowed claims.
- [ ] A publish dry run succeeds, and the exact tag/publish commands plus
      rollback procedure are recorded for the King's approval.
