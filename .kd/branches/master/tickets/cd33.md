# D4b: Run and publish compact ARM/x86 certification

## Goal

Run the compact D4 benchmark on controlled ARM and Linux/x86 hosts from the
same exact source, evaluate every selected gate without stopping at the first
measured miss, and publish the machine-readable evidence plus a concise honest
conclusion.

## Scope

- After `cb29` closes, run a fresh compact controlled ARM capture and retain its
  complete archive even when individual performance gates miss.
- Present the exact x86 resource plan, maximum duration, and hard dollar ceiling
  to the King and obtain explicit approval before creating paid compute.
- After approval, run the compact controlled x86 capture from the same source
  and benchmark schema, with complete pre/post semantic conformance.
- Combine the separate architecture archives only at evaluation time, list all
  selected-matrix failures together, and publish raw versioned JSON plus a
  readable report with reproducible commands and provenance.
- Close Phase D only if the selected compact release gates honestly pass;
  otherwise publish the measured miss and reopen or create the narrowly
  relevant optimization work without weakening the contract.

## Non-goals

Do not redesign benchmark infrastructure, change thresholds, claim exhaustive
A5 coverage, certify video or vLLM behavior, merge ARM and x86 measurements, or
launch paid compute without explicit approval. The legacy exhaustive matrix is
deferred for later deep investigation.

## Acceptance Criteria

- [x] Fresh controlled ARM and Linux/x86 archives are captured from identical
      exact source and compact schema, with valid pre/post conformance and no
      infrastructure, host-control, provenance, or evidence-integrity failure.
- [x] The x86 launch occurs only after the King reviews and explicitly approves
      the exact resource request, maximum duration, and hard dollar ceiling;
      no worker remains running after capture or failure.
- [x] Evaluation covers every selected compact coordinate on both profiles and
      architectures and reports all measured speed, regression, efficiency,
      and memory misses together rather than failing on the first miss.
- [x] Versioned raw JSON and a readable report preserve required samples,
      percentiles, confidence intervals, resource measurements, commands, and
      separate ARM/x86 host/build/runtime provenance.
- [x] Report/schema/currentness validation and clean-checkout reproduction of
      non-host-specific artifacts pass, and the report makes no exhaustive-A5,
      production, or video claim.
- [x] The Phase D epic and roadmap status reflect the actual compact result: a
      pass closes the selected release gate, while any miss remains explicit
      and drives narrowly scoped follow-up work.
