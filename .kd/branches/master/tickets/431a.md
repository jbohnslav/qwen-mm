# A3: Build the conformance corpus and comparator

## Goal

Create the repeatable evidence system that decides whether Rust matches the
pinned official implementation and localizes failures to a processing stage.

## Scope

- Use three tiers: small committed end-to-end goldens, compact rule fixtures,
  and seeded live differential tests against the pinned Python environment.
- Cover both model profiles, successful and failing inputs, batch ordering, and
  the text, image, and temporal rules required by the roadmap.
- Make failures actionable instead of reporting only a tensor hash mismatch.

## Acceptance Criteria

- [x] Compact rule cases cover factor-32 half ties, min/max pixel transitions,
      aspect-ratio limits, explicit dimensions, frame counts/sampling/timestamps,
      placeholder counts, and arithmetic/error boundaries.
- [x] Media cases cover raw strided RGB, JPEG/PNG/WebP, declared color modes,
      alpha/CMYK behavior, EXIF orientations, malformed/truncated inputs, mixed
      shapes, repeated/interleaved visuals, and resource limits.
- [x] Chat cases cover both pinned templates and the entire envelope frozen in
      A1, including unusual roles/options, Unicode, padding, and literal visual
      tokens.
- [x] The comparator enforces the A1 policy for keys, values, order, dtypes,
      strides, errors, and pixels, and checks grid/patch/placeholder invariants.
- [x] Pixel failures report maximum absolute and ULP error, RMSE, percentiles,
      count over threshold, and the first differing patch/channel coordinate.
- [x] Seeded live cases are reproducible; a failing case can be minimized and
      promoted to a committed regression fixture.
- [x] Fast smoke cases are suitable for pull requests and the full matrix has a
      documented nightly/reference-change entry point.

## Worklog

### 2026-07-31 — started and implementation plan

- Started A3 as the hand after A1 and A2 closed. Preserving the pre-existing
  uncommitted `DESIGN.md`, `README.md`, and `ROADMAP.md` changes; A3 work will
  stay scoped to the reference/conformance package, deterministic fixtures,
  tests, and documentation.
- A1 already freezes exact structural checks, stage-specific numeric bounds,
  pixel diagnostics, stable error categories, and resource limits. A2 already
  exports deterministic staged manifests with prompts, prepared media, sidecar
  metadata, official output arrays, errors, and provenance. A3 will consume
  those records rather than create a second oracle implementation.
- Planned delivery sequence: (1) implement a manifest/candidate comparator and
  invariant checker with structured stage-localized reports; (2) add compact
  geometry, temporal, error, media, chat, and batch rule fixtures; (3) add
  reproducible seeded live generation, failure minimization, and regression
  promotion; (4) wire a fast committed smoke gate and a documented full
  nightly/reference-change matrix into the existing Make/uv workflow.
- Comparator tests will deliberately inject key/order/dtype/stride/value/error
  and pixel mismatches, proving diagnostics include max absolute/ULP error,
  RMSE, percentiles, count over bound, and the first differing semantic
  coordinate. Corpus tests will validate coverage metadata so required cases
  cannot silently disappear.

### 2026-07-31 — comparator, corpus, and live runner implemented
