# B1: Define profiles, types, and limits

## Goal

Establish the dependency-light Rust contract that every later processor stage
uses: immutable local profiles, valid request/output types, configurable safety
limits, checked arithmetic, and stable categorized failures.

## Scope

- Load the two aliases and exact profile data frozen by A1 from local assets,
  validate behavior-changing constants and fingerprints, and reject drift
  rather than silently accepting an upstream-compatible-looking configuration.
- Define structured messages, supported content and tool-call items, visual
  occurrences/references, per-request options, encoded and caller-owned RGB
  image inputs, and the complete conditional prepared-output model.
- Keep parity-facing integer storage `int64` and pixel storage `float32`, with
  explicit shapes, row ordering, contiguity/stride expectations, and image
  replacement-range sidecar data.
- Implement the configurable defaults in the compatibility ADR, deterministic
  preflight ordering, checked count/byte/pixel/stride/capacity arithmetic, and
  the stable public error categories with structured context.

## Non-goals

Do not render templates, tokenize, decode or resize media, patchify pixels,
build Python bindings, or introduce a generic Hugging Face configuration layer.

## Acceptance Criteria

- [x] Offline loading resolves both frozen aliases to the expected revision,
      asset hashes, tokenizer/template identity, preprocessing constants, and
      canonical profile fingerprint.
- [x] Unknown aliases, changed revisions/assets/constants, malformed manifests,
      and stale fingerprints fail as `profile_mismatch`; they cannot fall
      through to media or internal errors.
- [x] Request types represent the entire declared Phase B text/image envelope
      and reject excluded options or invalid role/content/media combinations
      without relying on Python objects.
- [x] Prepared output types can represent every official conditional key with
      parity-facing `i64` metadata and `f32` pixels, exact ordering, and the
      adapter sidecar required by later vLLM work.
- [x] Default and caller-lowered resource limits cover every A1 image/text/batch
      dimension relevant to the shared types; boundary tests distinguish
      `resource_limit` from `arithmetic_overflow` and allocate nothing first.
- [x] All stable A1 error categories and deterministic validation precedence are
      encoded and unit-tested with structured diagnostic context.
- [x] `qwen-mm-core` remains Python-, Torch-, OpenCV-, and network-independent;
      its unit/doc tests, formatting, and Clippy checks pass.

## Worklog

### 2026-08-01 — ticket created

Scoped from ROADMAP B1 using A1's compatibility ADR/manifest and A4's Cargo
workspace as authoritative inputs.

### 2026-08-01 — implementation started

Started B1 as the only ready Phase B ticket. A collaboration subagent will
implement the scoped Rust foundation in the shared checkout; the Lord retains
ticket lifecycle, worklog, review, verification, and commit responsibility.

### 2026-08-01 — Rust foundation implemented

- Added modular stable errors/validation stages, immutable profile loading,
  Rust-native request/media/options, resource preflight, and parity output
  types under `qwen-mm-core`.
- Bundled profile loading validates canonical SHA-256 fingerprints and separately
  requires the two accepted immutable fingerprints, so malformed, stale, and
  internally recomputed-but-unaccepted manifests all fail as
  `profile_mismatch` without filesystem or network access.
- Added borrowed message, tool, encoded-image, strided-RGB, raw-frame, occurrence,
  and option types. Explicitly excluded upstream options remain representable
  only so they can be rejected with the frozen category.
- Added exact conditional `i64`/`f32` row-major matrices and ordered image/video
  integration sidecars, including nondecreasing request traversal checks.
- Added all ADR defaults, caller-lowered policies, checked `u64` arithmetic, and
  staged structure/profile/options/resource/geometry preflight.

### 2026-08-01 — Lord review and corrections

The initial implementation passed its own suite, but the Lord found two gaps
before acceptance. Workspace dependency specifications used compatible ranges
instead of exact pins, and explicit prepared-image dimensions were checked
against the 67,108,864 decoded-source limit rather than the independent
16,777,216 semantic prepared-image cap. The implementation was returned for
correction.

The final revision exact-pins Serde 1.0.229, serde_json 1.0.151, and SHA-2
0.10.9. `ResourceLimits` now models decoded-source and prepared-image caps
separately, rejects oversized image dimensions and min/max options during
resource preflight, and does not incorrectly apply the still-image cap to video.
Regression tests cover the interval between the two caps, option bypasses, and
sidecar request-order regressions.

### 2026-08-01 — final verification

- `make rust-check` passed workspace formatting, Clippy with `-D warnings`, 26
  core unit tests, all workspace tests, the core doctest, and the locked offline
  core build.
- Independent `make check` passed Ruff, the full Rust suite, all 30 reference
  tests, fixture/golden/corpus validation, conformance smoke, and a fresh wheel
  build/install/native-call smoke.
- `git diff --check` passed. The core has no Python, Torch, OpenCV, network,
  tokenizer, decoder, resize, or model-execution dependency.

All seven acceptance criteria are satisfied.
