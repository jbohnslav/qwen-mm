# B2: Implement tokenizer and chat rendering

## Goal

Reproduce the declared Qwen3-VL and Qwen3.5 text surfaces in native Rust so
rendered prompt bytes and all padded text arrays exactly match the pinned
official composed path.

## Scope

- Load and validate each local `tokenizer.json`, special-token configuration,
  and template asset through B1's immutable profile.
- Use the Rust `tokenizers` crate for tokenization and implement only the chat
  surface frozen in A1: roles/content, tools and tool calls/results, generation
  prompts, vision IDs, padding, and profile-specific options.
- Preserve the Qwen3.5 reasoning/thinking and whitespace behavior and reject
  Qwen3.5-only options on the Qwen3-VL profile.
- Accept deterministic visual replacement information so text processing can
  emit exact expanded prompts, `input_ids`, `attention_mask`, and
  `mm_token_type_ids` without performing image processing itself.

## Non-goals

Do not add arbitrary Jinja/template overrides, truncation, documents, audio,
network asset loading, a Python callback, or permissive behavior outside the
accepted compatibility surface.

## Acceptance Criteria

- [ ] Rendered and visual-expanded prompts match the A2 UTF-8 bytes exactly for
      both profiles, including whitespace, Unicode, special tokens, tool JSON,
      generation prompts, vision IDs, and Qwen3.5 thinking/reasoning cases.
- [ ] Token IDs and special-token placement match exactly for committed goldens
      and the complete A3 chat corpus on both profiles.
- [ ] Padding uses the profile-specific pad token and produces exact `int64`
      `attention_mask` and `mm_token_type_ids` values, shapes, order, and
      C-contiguous row strides.
- [ ] Visual placeholder counts and replacement spans are checked against the
      supplied occurrence/grid plan; missing, extra, literal, interleaved, and
      repeated visual tokens follow the frozen valid/error behavior.
- [ ] Unsupported roles/options, malformed tool content, profile-option
      mismatches, and configured token-limit failures return the correct stable
      B1 category and deterministic precedence.
- [ ] Tokenizer/template assets are loaded locally and hash-validated; tests
      prove no Python, Hugging Face, Qwen VL Utils, or network fallback exists.
- [ ] The added dependency versions are exact-pinned and justified; core unit,
      conformance-smoke, format, Clippy, and doc tests pass.
