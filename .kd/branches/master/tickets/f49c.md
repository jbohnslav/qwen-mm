# Raise image24 t8 parallel efficiency on ARM and x86

## Goal

Raise shipping `image24/t8` parallel efficiency to the frozen `E_8 >= 0.6`
gate for both profiles on both controlled architectures while retaining the
processor-owned bounded thread pool.

## Scope

- Profile scheduling, work partitioning, synchronization, allocator pressure,
  and resizer behavior at `t1` and `t8` on ARM and x86.
- Correct bottlenecks within the existing eight-thread budget and verify
  deterministic results and stable errors at all supported thread counts.
- Measure each change on both profiles and architectures before accepting it.

## Non-goals

Do not relax the efficiency formula or `0.6` threshold, add hidden threads,
oversubscribe through a nested pool, or trade away compact `t1` speed,
conformance, or memory gates.

## Acceptance Criteria

- [ ] All four `efficiency/{arm64,x86_64}/{qwen3-vl-8b,qwen3.5-9b}/image24/t8`
      gates report `E_8 >= 0.6` under the frozen compact protocol.
- [ ] The implementation owns one bounded pool, honors the same eight-thread
      budget as the official path, and preserves outputs, ordering, and stable
      errors across supported thread counts.
- [ ] Before/after evidence explains the dominant scaling loss and shows no
      regression in selected speed, noise, or transient-memory gates.
- [ ] Full image conformance, repository correctness, and D4 evidence
      validation pass with exact-source provenance recorded.
