# Run the bounded multithreaded optimization pass for v0.1

## Goal

Make one profile-driven pass over qwen-mm's t8 scaling before v0.1, prioritizing
the larger x86 gap while retaining deterministic processor-owned bounded
parallelism. Improve user-visible t8 latency where low-risk evidence supports
it; the original `E_8 >=0.6` target remains published but is not the close
condition.

## Scope

- Profile t1/t8 scheduling, work partitioning, synchronization, allocator
  pressure, serial fractions, and resizer behavior on x86 first and ARM second.
- Apply only bounded, low-risk changes within the same eight-thread budget.
- Measure each change on both profiles and architectures and retain it only
  when t8 improves without harming t1, correctness, memory, or pool semantics.
- Publish the final absolute speed and internal efficiency honestly even if the
  former 60% target remains unmet.

## Non-goals

Do not relabel the old certification, add hidden threads, oversubscribe through
a nested pool, create architecture-dependent outputs/errors, or trade away t1
speed, conformance, or bounded memory. Avoid speculative scheduler rewrites
once the ranked low-risk opportunities are exhausted.

## Acceptance Criteria

- [ ] Current x86 and ARM profiles quantify the dominant t8 scaling losses,
      including serial work, scheduling/synchronization, allocator contention,
      and per-stage core utilization.
- [ ] At least one ranked low-risk improvement is measured in isolation and
      retained only if it repeatably improves t8 without a material t1,
      memory, or correctness regression; if none qualifies, the rejected
      options and evidence are documented.
- [ ] The implementation owns one bounded pool, honors the same eight-thread
      budget as the official path, and preserves outputs, ordering, and stable
      errors across supported thread counts.
- [ ] Before/after absolute t1/t8 latency, internal efficiency, CPU utilization,
      and transient memory are published separately for both profiles and
      architectures; remaining misses stay explicit.
- [ ] Full image conformance, installed-wheel checks, repository correctness,
      and relevant evidence validation pass with exact-source provenance.
