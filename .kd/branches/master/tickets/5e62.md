# B7: Integrate the serial single-request image path

## Goal

Compose the Phase B text and image stages into one public native Rust
single-request processor that matches the full pinned official composed path
for both profiles and has no Python runtime fallback.

## Scope

- Plan visual occurrences in structured-message order, resolve encoded and raw
  RGB inputs, expand image placeholders/ranges, render/tokenize text, prepare
  pixels, and assemble grids plus the complete official conditional output set.
- Support text-only, one-image, multi-image, interleaved, and repeated-reference
  requests inside one request, with deterministic occurrence and patch order.
- Apply B1's validation/error precedence and resource policy across the entire
  operation, including cross-stage counts and materialized-output capacity.
- Add an end-to-end Rust test/candidate entry point that the A3 conformance
  tooling can run without invoking the reference implementation at runtime.

## Non-goals

Do not add multiple-request batching, the two-phase caller-destination API,
PyO3/NumPy ownership, parallel execution, performance claims, video, caching,
or vLLM integration.

## Acceptance Criteria

- [ ] Both frozen profiles pass text-only, one-image, interleaved multi-image,
      and repeated-image committed/live differential cases without Python,
      Hugging Face, Qwen VL Utils, Pillow, or TorchVision at runtime.
- [ ] Rendered/expanded prompt bytes, output-key presence/order, `input_ids`,
      `attention_mask`, `mm_token_type_ids`, `image_grid_thw`, occurrence order,
      placeholder counts, replacement ranges, shapes, and strides are exact.
- [ ] Raw/lossless and lossy encoded `pixel_values` satisfy the immutable
      end-to-end tolerances and grid/patch/placeholder invariants, with A3's full
      numerical diagnostics when a comparison fails.
- [ ] Text-only requests omit image outputs; invalid placeholder/media counts,
      malformed structure/options/media, profile drift, resource excess, and
      overflow return the exact stable category in deterministic precedence.
- [ ] Repeated references preserve occurrence semantics and output ordering;
      tests prove no occurrence is omitted, reordered, or processed through an
      untracked duplicate stage.
- [ ] The serial operation either returns a complete consistent result or an
      error; no partially observable output survives a failed stage.
- [ ] A documented offline command runs Phase B end-to-end conformance for both
      profiles, and the full repository correctness suite passes from a clean
      checkout.
