# D3: Apply profile-driven fusion and arenas

## Goal

Remove measured allocation, copy, and memory-lifetime bottlenecks without
changing the official output contract. Use C1's exact-capacity two-phase API to
reuse bounded scratch, fuse normalization with final layout writes, and fill
caller-owned destinations only where D1 demonstrates a material benefit.

## Scope

- Turn each proposed optimization into an isolated experiment tied to a D1
  profile rank, allocation/copy count, or buffer-lifetime observation.
- Reuse bounded per-processor or per-worker scratch without retaining caller
  data, leaking memory across failures, or scaling scratch with final output
  size or unbounded workload history.
- Fuse normalization, channel/layout permutation, temporal duplication, and
  patch writes when doing so removes measured intermediates while preserving
  the frozen operation order and numeric tolerance.
- Extend direct caller-destination execution through the Python/NumPy boundary
  where safe, retaining exact preflight, no-partial-write, ownership, alias,
  failure-lifetime, shape, dtype, and stride guarantees.
- Measure every change independently against its pre-change baseline, document
  which allocation/buffer/copy disappeared, and rerun full conformance before
  stacking the next optimization.
- Leave a final allocation/buffer diagram or census that demonstrates there is
  no full `float32` CHW intermediate image in the optimized path.

## Non-goals

Do not broaden the compatibility envelope, relax numeric tolerances, introduce
compact/bf16 output modes into the headline path, add cross-request caching,
or claim D4 certification. D2 owns parallel scheduling; Phase E owns video.

## Acceptance Criteria

- [x] Every landed optimization cites a D1 profile/counter finding and includes
      isolated before/after wall time, CPU time, allocation/copy, and peak
      transient-live-byte evidence on representative affected workloads.
- [x] Scratch and arena ownership is bounded per processor/worker, is safe
      across reuse and failure, does not retain caller-owned media, and has
      focused lifetime, limit, and multi-instance tests.
- [x] The optimized path writes normalized patch layout directly to the exact
      final or caller-owned destination without materializing a full
      `float32` CHW intermediate image; the buffer census makes this verifiable.
- [x] Plan/execution preflight, stale-plan rejection, destination validation,
      no-partial-write semantics, NumPy ownership, dtypes, shapes, strides, and
      data-pointer behavior remain unchanged.
- [x] Both frozen profiles pass full image conformance after each isolated
      optimization with unchanged tolerances, plus focused numerical tests for
      fused stage ordering and edge values.
- [x] Final profile and allocation evidence enumerates removed buffers/copies,
      remaining hotspots, arena high-water behavior, and any optimization
      rejected because its measured benefit or correctness evidence was
      insufficient.
- [x] The full repository correctness suite passes from a clean checkout.

### 2026-08-03 — three isolated experiments evaluated

Measured on the Apple M4 with release builds, one thread, two warmups, seven
samples, both frozen profiles, and `image24`/`ragged24`/`rgb24`. All four exact
implementation patches, native identities, input/output/sidecar signatures,
raw samples, and the complete protocol are in `benchmarks/d3-evidence-v1/`.
The local timings are explicitly inconclusive because the host was visibly
contended; they are retained without smoothing and are not release evidence.

1. Direct positive-stride resize removed all 24 `resize.packed_source` events
   per representative operation. It removed 25.7-56.5 MB of allocation/copy,
   and reduced peak transient bytes by 2.35 MB. The local timing delta is
   inconclusive.
2. Transferring owned decoded storage on encoded no-resize removed five more
   allocations/copies and 9.83 MB in `ragged24`. The deterministic memory/copy
   reduction is the reason it remains. Raw borrowed no-resize correctly keeps
   its required owned-output copy.
3. A fixed 3,072-byte per-call normalization lookup was bit-exact against the
   frozen expression for all `u8` values and both profiles, but was rejected
   after controlled measurement.

The exact counters show no allocation, copy, or owned-transient regression,
and all 24 variant/profile/case comparisons have bit-exact official arrays and
metadata sidecars.

The controlled same-worker Modal selection run completed on a nonpreemptible,
single-use 16-CPU/32-GiB Linux x86 worker. The lookup made the targeted
normalize/patchify stage 35-39% slower in all six workloads and regressed the
whole operation in four of six comparisons against no-LUT, so it was removed.
The exact validated archive is `modal-selection.zip`, SHA-256
`addffbb99886b84057421b6af2bf09034ed6abba9f2d27cabe4e9f08e59daaa0`.
It retains 24 raw coordinates, four patches/binaries/build logs, host/resource
and process-affinity provenance, and an integrity manifest. Its 369.006-second
elapsed-worker estimate is $0.31067, excluding image construction and provider
billing adjustments. This remains D3 selection evidence, not replicated D4
certification.

Selected source keeps direct-stride resize and encoded ownership transfer. It
removes 24-29 allocations/copies and 25.7-56.5 MB per representative operation,
with no exact-output, sidecar, transient-memory, or process-RSS regression. The
measured no-LUT patch retained an unreachable lookup helper/test; clean final

`14c2a6888efad7fdc1a8fd98c6a34bd7fc5597ebb56914832eed58bf50533bc8`,
