# D3: Apply profile-driven fusion and arenas

## Goal

Remove measured allocation, copy, and memory-lifetime bottlenecks without
changing the official output contract. Use C1's exact-capacity two-phase API to
reuse bounded scratch, fuse normalization with final layout writes, and fill
caller-owned destinations only where D1 demonstrates a material benefit.

## Scope

- Turn each proposed optimization into an isolated experiment tied to a D1
  profile rank, allocation/copy count, or buffer-lifetime observation.
- Reuse bounded per-processor or per-worker scratch without retaining caller
  data, leaking memory across failures, or scaling scratch with final output
  size or unbounded workload history.
- Fuse normalization, channel/layout permutation, temporal duplication, and
  patch writes when doing so removes measured intermediates while preserving
  the frozen operation order and numeric tolerance.
- Extend direct caller-destination execution through the Python/NumPy boundary
  where safe, retaining exact preflight, no-partial-write, ownership, alias,
  failure-lifetime, shape, dtype, and stride guarantees.
- Measure every change independently against its pre-change baseline, document
  which allocation/buffer/copy disappeared, and rerun full conformance before
  stacking the next optimization.
- Leave a final allocation/buffer diagram or census that demonstrates there is
  no full `float32` CHW intermediate image in the optimized path.

## Non-goals

Do not broaden the compatibility envelope, relax numeric tolerances, introduce
compact/bf16 output modes into the headline path, add cross-request caching,
or claim D4 certification. D2 owns parallel scheduling; Phase E owns video.

## Acceptance Criteria

- [ ] Every landed optimization cites a D1 profile/counter finding and includes
      isolated before/after wall time, CPU time, allocation/copy, and peak
      transient-live-byte evidence on representative affected workloads.
- [ ] Scratch and arena ownership is bounded per processor/worker, is safe
      across reuse and failure, does not retain caller-owned media, and has
      focused lifetime, limit, and multi-instance tests.
- [ ] The optimized path writes normalized patch layout directly to the exact
      final or caller-owned destination without materializing a full
      `float32` CHW intermediate image; the buffer census makes this verifiable.
- [ ] Plan/execution preflight, stale-plan rejection, destination validation,
      no-partial-write semantics, NumPy ownership, dtypes, shapes, strides, and
      data-pointer behavior remain unchanged.
- [ ] Both frozen profiles pass full image conformance after each isolated
      optimization with unchanged tolerances, plus focused numerical tests for
      fused stage ordering and edge values.
- [ ] Final profile and allocation evidence enumerates removed buffers/copies,
      remaining hotspots, arena high-water behavior, and any optimization
      rejected because its measured benefit or correctness evidence was
      insufficient.
- [ ] The full repository correctness suite passes from a clean checkout.
