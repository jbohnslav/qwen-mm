# Final v0.1 usability and Rosetta Stone approval gate

## Goal

After the focused usability implementation tickets close, rewrite the Rosetta
Stone against the finished public API and make the remaining delta from the
official examples as small and unsurprising as possible. The King personally
reviews and approves this final experience before v0.1 ships.

## Implementation tickets

- `5fb8` — familiar `Processor.from_pretrained` construction using the
  canonical short names `Qwen3` and `Qwen3.5` or exact Hugging Face model IDs.
- `6eea` — direct local-path, URL, data-URI, and OpenAI-style image sources.
- `70c3` — concise single-request preparation, left-padding compatibility, and
  mapping-style prepared outputs.

## Scope

- Inventory every official Qwen3-VL and Qwen3.5 code sample relevant to the
  declared v0.1 text/still-image envelope, recording its authoritative source
  and pinned version or revision.
- Include the official Hugging Face model and documentation pages,
  `qwen-vl-utils`, vLLM, and SGLang examples, plus relevant Qwen-owned
  repositories, cookbooks, and multimodal plugins discovered during the
  inventory. Include key downstream Qwen consumers such as LLaMA-Factory and
  ModelScope SWIFT where their dataset or request schemas reveal additional
  usability requirements. Cover text-only, single-image,
  multi-image/interleaved, and video examples even when video is classified as
  deferred rather than supported.
- Classify each sample as supported in v0.1, intentionally unsupported, or
  deferred to video/vLLM; omissions must be explicit rather than accidental.
- Write the shortest clear installed-wheel qwen-mm equivalent for each
  supported flow: text-only, one image, multiple/interleaved images, mixed
  formats and shapes, batched requests, raw RGB, options, outputs, and errors.
- Make the primary review document a focused Rosetta Stone: for each distinct
  official flow, show the small relevant upstream preprocessing excerpt and
  the exact qwen-mm equivalent immediately after it. Keep source-audit detail
  and broad classifications in a secondary inventory rather than forcing a
  reader through them before seeing the code comparison.
- Review constructor inputs, request schema, naming, return values, metadata,
  thread controls, exceptions, snapshot discovery, and failure messages for
  accidental complexity.
- Simplify the API or add thin ergonomic helpers where the comparison exposes
  real friction, without opaque callbacks, unrestricted fallback, or a second
  competing request model. Filesystem and network I/O are triggered by the
  explicit model or media value supplied by the caller.
- Add a familiar `Processor.from_pretrained(model)` happy path. It accepts
  the canonical short names `Qwen3` and `Qwen3.5` plus the exact
  supported Hugging Face model IDs, resolves them to qwen-mm's tested profile
  and pinned revision, and downloads through the normal Hugging Face cache when
  the snapshot is absent. Preserve an explicit offline/cache-only option and
  keep `from_huggingface_cache` as the lower-level reproducible path.
- Accept caller-supplied local paths and HTTP(S) image URLs directly in public
  image content, normalizing them to the existing owned-byte/index model before
  native preprocessing. Cover both the Qwen `{"type": "image", "image": ...}`
  form and the Qwen3.5 OpenAI-style `image_url` form. If the caller supplies an
  HTTP(S) URL, qwen-mm fetches it directly: there is no opt-in permission flag,
  private-network filtering, security policy, or warning ceremony. Ordinary
  resource ceilings and actionable network errors remain reliability behavior,
  not a gate on the caller's explicit request.
- Rewrite the Rosetta Stone only after `5fb8`, `6eea`, and `70c3` close. Preserve
  the official messages verbatim wherever the flow is supported and make the
  qwen-mm side differ only where its preprocessing/output boundary genuinely
  differs.
- Make the root README the user entrypoint with installation, a one-screen
  quickstart, supported/unsupported matrix, threading guidance, and links to
  deeper examples.
- Turn published examples into installed-wheel tests so documentation cannot
  drift from the actual interface.

## Non-goals

Do not add encoded video, arbitrary PIL/tensor compatibility, a vLLM adapter,
unrestricted model/revision fallback, or generic Hugging Face processor
emulation merely to make an official sample appear supported. Model downloads
remain limited to known compatibility profiles and pinned revisions. Explicit
image URLs are not subjected to a library security policy. Other unsupported
examples are documented and deferred honestly.

## Acceptance Criteria

- [x] A versioned comparison table covers every relevant official sample for
      both pinned profiles and identifies supported, unsupported, and deferred
      behavior with no unexplained gap.
- [x] `5fb8`, `6eea`, and `70c3` are closed with their installed-wheel tests and
      full repository verification passing.
- [x] `Processor.from_pretrained` accepts `Qwen3`, `Qwen3.5`, and both
      canonical supported model IDs, downloads only pinned processor artifacts,
      and supports an offline/cache-only mode.
- [x] Qwen-style direct path/URL images and Qwen3.5-style `image_url` content
      normalize to the existing deterministic byte/index core with bounded I/O.
- [x] The Rosetta Stone is rewritten against the final API; supported qwen-mm
      examples retain the official message objects and are materially similar
      in construction and call-site complexity.
- [x] Every supported comparison has a concise, runnable qwen-mm equivalent
      exercised from a freshly installed wheel on the declared platforms.
- [x] The happy path—from import and processor construction through prepared
      arrays—is understandable without reading implementation or benchmark
      code, and common errors tell users how to correct the request.
- [x] Root documentation states the exact v0.1 scope, model/snapshot
      prerequisites, input forms, output contract, threading behavior, and
      performance-claim boundaries.
- [x] Full conformance, binding/ownership, wheel, and documentation-example
      tests pass after any ergonomic changes.
- [ ] The King reviews the final API and official-example comparison and gives
      explicit approval; this criterion cannot be self-approved by an agent.
