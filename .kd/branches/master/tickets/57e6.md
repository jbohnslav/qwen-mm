# v0.1 still-image and text release

## Goal

Cut an honest, usable first Python release of qwen-mm's CPU text/still-image
processor for the two pinned Qwen profiles on native macOS ARM and Linux x86.
The release is allowed to precede strict 122/122 D4 certification, encoded
video, and vLLM production integration.

## Child and Dependency Tickets

- ARM optimization pass / `725c` — make a bounded profile-driven pass over the
  weakest ARM paths, especially raw RGB.
- Multithreaded optimization pass / `f49c` — pursue high-value scaling wins on
  x86 and ARM without making the old 60% target a release threshold.
- Usability review / `7544` — compare the installed API with every official
  example relevant to v0.1 and require the King's approval of the experience.
- Release artifacts / `e8d1` — documentation, metadata, native wheels,
  clean-install verification, changelog, tag, and publishing dry run.

## Release Contract

- Functional support and correctness remain strict for the declared v0.1
  image/text envelope.
- Performance claims name only measured passing workloads; the original D4
  `MISS` remains published and is not relabeled.
- Completing the two bounded optimization passes blocks the cut, but reaching
  the old `E_8 >=0.6` and relative-memory `<=0.5x` targets does not.
- The usability review is the product approval gate: the King must inspect and
  approve the final public API and official-example comparison.
- Phase E video and Phase F vLLM/production work are explicitly outside v0.1.

## Acceptance Criteria

- [ ] `725c` and `f49c` complete their bounded, profile-driven optimization
      passes with full correctness verification and updated measurements.
- [ ] `7544` demonstrates simple installed-wheel equivalents for every relevant
      official sample, documents unsupported samples honestly, and receives
      explicit approval from the King.
- [ ] `e8d1` produces reproducible native macOS ARM and Linux x86 artifacts,
      complete user-facing release documentation, and a successful clean
      publish/install dry run.
- [ ] The final v0.1 report preserves strict certification results separately,
      states the narrower support/performance claims, and validates from the
      exact release source.
- [ ] Version `0.1.0` is tagged or published only after every dependency closes
      and the King explicitly approves the release candidate.
